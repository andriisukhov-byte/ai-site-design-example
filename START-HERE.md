# Начните отсюда

Это рабочая копия маркетингового сайта Acme. На ней показано, как AI собирает страницы из готовых блоков дизайн-системы по брифу или по готовому тексту от маркетинга. Копия сделана как учебный пример для дизайнеров: её можно запускать, ломать и надстраивать своими скиллами.

Всё, что дальше по тексту называется «система», — это три вещи: блоки (`packages/blocks`), правила (`ai/`) и скиллы Claude Code (`.claude/skills`).

## Запуск

Нужны **Node.js 22.13+** и **PostgreSQL** (`brew install postgresql@15`).

```sh
npm run setup   # один раз, ~2 минуты: зависимости, своя база в .pgdata, контент, все генерации
npm run dev     # каждый раз
```

- сайт: http://localhost:4321
- админка CMS: http://localhost:3000/admin (`admin@aa.aa` / `admin`)

Если порт 5432 занят другим Postgres, запустите `PGPORT=5544 npm run setup`.

## Что посмотреть в первую очередь

**1. Готовые генерации.** У каждой страницы в `data/ai-page-generation/<батч>/` лежат вход и выход: `brief.md` (что просили), `lp.md` (готовый текст от маркетинга, если был), `pages.json` (что собрал AI) и `review.md` (что нашёл независимый ревьюер).

| Страница | Что показывает |
|---|---|
| http://localhost:4321/ai-receptionist-for-cleaning-companies-v3/ | трек A: текст от маркетинга перенесён без правок (`lp.md` → блоки) |
| http://localhost:4321/ai-receptionist-for-cleaning-companies-v5/ | трек B: полное ТЗ от маркетинга, текст написан системой |
| http://localhost:4321/ai-intake-agent-for-law-firms/ | трек B с комплаенс-ограничением в ТЗ |
| http://localhost:4321/ai-receptionist-for-dental-clinics/ | облегчённый вертикальный лендинг |
| http://localhost:4321/ai-receptionists-for-pest-control-companies/ | статья-рейтинг (шаблон article) |

Версии cleaning v2 → v5 — это один и тот же лендинг, пересобранный после каждого раунда фидбека. Их удобно сравнивать вместе с `docs/page-generation*/` (разборы со скриншотами) и `review.md` каждого батча.

**2. Витрина блоков.** От http://localhost:4321/blocks/ до `/blocks-9/` показаны все 47 блоков дизайн-системы.

**3. Правила.** Читать в таком порядке:
- `ai/instructions/page-compose.md` — как из брифа получается последовательность блоков;
- `ai/contracts/block-contracts.md` — какой блок для чего и сколько текста в него влезает;
- `ai/contracts/copy-rules.md` — правила текста;
- `ai/contracts/lp-handoff.md` — как текст от маркетинга передаётся в систему.

**4. Скиллы.** `.claude/skills/create-page/SKILL.md` (собрать страницу) и `.claude/skills/create-block/SKILL.md` (добавить блок в дизайн-систему).

## Попробовать самому

Откройте папку в Claude Code и напишите, например:

```
/create-page AI receptionist для автосервисов. Лендинг: hero, боли, как работает, интеграции, FAQ, CTA.
```

Скилл соберёт бриф, подберёт блоки, напишет текст по правилам, проверит его гейтами (`npm run qa:copy`) и импортирует страницу в CMS как черновик. Чтобы увидеть её на сайте, опубликуйте страницу в админке.

## Как делать свои надстройки

- **Свой скилл.** Создайте `.claude/skills/<имя>/SKILL.md` по образцу `create-page`: шаги, гейты, что считается готовым. Claude Code подхватит его автоматически.
- **Свои правила.** Правила текста и композиции лежат в `ai/contracts/` и `ai/instructions/`, а скиллы ссылаются на них, а не дублируют. Правило меняется в одном месте.
- **Свой блок.** Через `/create-block`: дизайн внутри системы → проверка → регистрация (`packages/blocks/src/registry.ts`, схема, рендерер в `apps/web/src/components/blocks/`, стили в `apps/web/src/styles/blocks/`).
- **Своя дизайн-система.** Токены и базовые стили лежат в `packages/styles`. Если заменить их и рендереры, вся логика генерации останется прежней.

Подробно о том, как всё устроено: `README.ru.md` (или `README.md`), `ACME-WEBSITE-DESIGN-WORKFLOW.md` и `CLAUDE.md`.

## Что убрано из этой копии

- реальное название продукта и его логотипы: везде стоит условное **Acme** (домен `acme.example`), знак заменён нейтральным кольцом. Палитра, шрифты, сетка и все блоки остались как в оригинале;
- история git, токены и ключи, все `.env` с реальными значениями (`npm run setup` генерирует локальные заново);
- адреса staging и превью, ID форм Formspree, конфиги деплоя;
- внутренняя переписка, фидбек-сессии, документы миграции и инфраструктуры, названия компании-разработчика и её клиентов;
- медиафайлы старого контента: на старых страницах часть картинок будет пустой, а генерации и блоки это не затрагивает.

Не работают отправка форм наружу, деплой и синхронизация со старым сайтом: всё это требует внутренних ключей. Скрипты оставлены как пример.

## Важно

Не добавляйте в этот репозиторий реальные данные клиентов, ключи, а также персональные или медицинские данные (PHI). Это касается в том числе примеров для медицинских вертикалей вроде дентал-лендинга: только вымышленные данные.
